GIT INIT

Git хранит историю изменений твоего проекта. Семь команд, с которых начинают все.

01 / Зачем

Представь, что ты переписал файл, и стало хуже. Без Git придётся вспоминать, что там было. Git помнит всё: каждую версию, кто и когда её сделал, и позволяет вернуться на любую.

  • История изменений — можно откатить любой файл на любой момент
  • Работа вдвоём без «файла-финала_2_НЕ_ТРОГАТЬ.docx»
  • История не боится: коммиты не пропадут, пока репозиторий на месте
Три слова, которые нужно понять сразу:
Рабочая папка — файлы, которые ты редактируешь.
Индекс (staging) — то, что ты отметил к следующему сохранению.
Репозиторий — история, всё что было закоммичено.
Работает всегда по этой цепочке: рабочая папка → add → индекс → commit → история

02 / Настройка (один раз)

Git подписывает каждый коммит именем и почтой. Настрой их один раз для всего компьютера:

terminal
git config --global user.name "Kirill" git config --global user.email "kirill@example.com"
Что делает

--global означает «для всех проектов на этом компьютере». Если убрать этот флаг — настройка сохранится только для текущего проекта.

Посмотреть, что настроено:

terminal
git config --list user.name=Kirill user.email=kirill@example.com

03 / Создать репозиторий

git init
git init

Создаёт в текущей папке скрытую папку .git — хранилище всей истории. Выполни один раз в папке проекта.

После этого в терминале рядом с папкой появится ветка main (раньше master).

git status
git status

Показывает, что сейчас происходит: какие файлы изменены, что отмечено к сохранению, что лежит в последнем коммите. Самая полезная команда — заглядывай сюда постоянно.

terminal
git status On branch main Untracked files: (use "git add <file>" to include in what will be committed) index.html style.css nothing added to commit yet

Untracked files — Git ещё не знает про эти файлы. Он не следит за папкой автоматически, файлы нужно добавлять руками.

04 / Сохранить изменения

git add
git add index.html // один файл git add . // всё сразу

Кладёт файл в индекс — «корзину» перед следующим коммитом. Так можно отправить в коммит только часть файлов, а остальное оставить несохранённым.

git commit
git commit -m "описание, что изменилось"

Записывает содержимое индекса в историю. Флаг -m обязателен — без него Git откроет редактор и попросит написать сообщение вручную.

Сообщение пишут в прошедшем времени: не «исправил баг», а «исправил баг с меню».

Вот как файл движется по цепочке:

Рабочая папкафайлы на диске
── git add ──▶
Индексотмечено к сохранению
── git commit ──▶
Историярепозиторий

Типичный рабочий цикл — три команды подряд:

terminal
git status // что изменилось git add . // отметить всё git commit -m "первая версия сайта" [main (root-commit) 1a2b3c4] первая версия сайта 2 files changed, 120 insertions(+) create mode 100644 index.html create mode 100644 style.css

05 / История

git log
git log

Показывает все коммиты от новых к старым: хеш, автора, дату и сообщение. Флаг --oneline сжимает каждый до одной строки — пригодится, когда коммитов много.

terminal
git log --oneline a1b2c3d поправил отступы в меню 9f8e7d6 добавил тёмную тему 1a2b3c4 первая версия сайта
git diff
git diff

Показывает разницу построчно: строки с + добавлены, с − удалены. Вызывай до коммита, чтобы проверить, что именно ты сохраняешь.

Подсказка: q выходит из длинного списка в git log, а q или стрелки — из режима просмотра в git diff.

06 / .gitignore — что не коммитить

В папке проекта создай файл .gitignore и перечисли то, что не нужно в истории:

node_modules/     // зависимости — их всегда ставят заново
.vscode/          // настройки редактора
*.log
.DS_Store

Файл нужен для того, чтобы случайно не отправить в репозиторий пароли, ключи или тысячи лишних файлов.

07 / Итого

шпаргалка
git config --global user.name "Имя" git config --global user.email "почта" git init git status git add . git commit -m "сообщение" git log --oneline git diff

Следующий шаг, когда освоишь это: git clone, git pull, git push — работа с GitHub и чужой папкой.
